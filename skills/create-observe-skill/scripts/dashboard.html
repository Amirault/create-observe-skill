    How to read it

    • Runs: an interactive run starts at the skill's slash command or Skill tool call (or a continue after a report) and ends at its report, else at its last message before the next human prompt. A subagent run (such as an evaluation harness replaying the skill) spans its subagent, first to last event.
    • Delivered: the outcome is one of the profile's delivered labels. Without an outcome line, a run whose final message links a pull request counts as PR OPENED, marked with *.
    • Verdict: a permutation test (2,000 shuffles) asks how often a gap as large as the one between the two windows appears when runs are dealt at random. Better or Worse when that happens less than 5% of the time (p < 0.05); leaning under 20%. The headline combines the median delivered run and the delivery rate. Small windows rarely conclude: widen the window to confirm a trend.
    • Attribution: between two transcript events the gap goes to the running tool (the one ending last when several run), else to the LLM when the model speaks next, or to Human wait when a person does. Waits on a subagent are replaced by what that subagent did, recursively; the rest is a Stall & handoff (stream cut off and retried, orchestrator returning before the work is done, agent start-up).
    • Shell commands are classified from their text, heredocs, quoted strings and comments removed: the profile's repository commands first, then git commit → pre-commit suite (the hooks it runs); test and build runners → build & test; sleep / until → polling.
